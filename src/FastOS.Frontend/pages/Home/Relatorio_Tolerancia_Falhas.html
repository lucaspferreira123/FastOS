1. Introdução

Este relatório documenta a implementação e os testes de tolerância a falhas no sistema FastOS, especificamente o mecanismo de detecção de queda do servidor e reconexão automática por parte do cliente.

O objetivo é demonstrar que o sistema é capaz de identificar quando o servidor se torna indisponível e notificar o usuário em tempo real, realizando tentativas automáticas de reconexão sem necessidade de intervenção manual do usuário.

2. Descrição da Solução Implementada

2.1 Componentes

Componente Localização Responsabilidade
Endpoint /health Program.cs Retorna status 200 OK quando o servidor está online
Script reconnect.js wwwroot/js/reconnect.js Polling periódico, detecção de falha e exibição do banner
Partial _SidebarMenu.cshtml Views/Shared/ Inclui o script em todas as páginas autenticadas

2.2 Fluxo de Funcionamento

  • A cada 3 segundos, o frontend realiza uma requisição GET /health
  • Se o servidor responder com 200 OK → sistema operando normalmente, nenhuma ação
  • Se a requisição falhar → banner vermelho é exibido com contador de tentativas
  • O intervalo entre tentativas dobra a cada falha (backoff exponencial): 3s → 6s → 12s → 24s → máx. 30s
  • Quando o servidor voltar → banner verde exibido e página recarregada automaticamente em 2 segundos

2.3 Código do Endpoint de Health Check

// Program.cs
app.MapGet("/health", () => Results.Ok(new {
    status = "online",
    timestamp = DateTime.Now
})).AllowAnonymous();

5. Análise dos Resultados

O mecanismo de tolerância a falhas implementado demonstrou comportamento correto em todos os cenários testados. Os principais pontos observados foram:

  • Detecção rápida: a queda do servidor foi detectada em aproximadamente 3 segundos após o encerramento do processo
  • Feedback visual imediato: o banner vermelho foi exibido em todas as páginas autenticadas do sistema
  • Backoff exponencial: o intervalo entre tentativas aumentou progressivamente, evitando sobrecarga desnecessária na rede
  • Recuperação automática: ao retornar, o servidor foi detectado sem intervenção do usuário e a página foi recarregada automaticamente
  • Transparência: o usuário foi informado em tempo real sobre o estado da conexão durante todo o período de indisponibilidade

6. Conclusão

A implementação do mecanismo de detecção de falhas e reconexão automática no sistema FastOS atende aos requisitos de tolerância a falhas propostos. O cliente web é capaz de identificar a indisponibilidade do servidor de forma autônoma, notificar o usuário de maneira clara e realizar tentativas de reconexão com estratégia de backoff exponencial, minimizando o impacto de falhas temporárias na experiência do usuário.
